# Глава → курс

Переносимый конвейер: глава учебника по геологии/геофизике → проверенный **учебный слой** →
**демо-курс для новичка** (путь из шагов, страницы шагов со «стр. N», задания с проверкой, карточки,
конспект, карта связей, иллюстрации кодом, ролики 9:16 и 16:9).

## Посмотреть готовые курсы

Общая стартовая страница — `runs/index.html`. Она показывает собранные курсы и доступные видеоразборы.
Страница обновляется при сборке курса и отдельно командой `python -m kmd library`.
Для просмотра через HTTP запустите `python -m kmd serve`. Адрес — `http://127.0.0.1:8766/`.
В каждом курсе раздел «Медиа» ведёт к видео, анимации или разбору цитат в конкретном уроке.
По таймкодам в тексте видео можно перейти к нужному моменту и открыть источник утверждения.

Откройте в браузере файл (сервер и интернет не нужны):

| Глава | Выборка | Курс |
|---|---|---|
| Латышова, гл. V §17–20 | обучение | `runs/latyshova/site/index.html` |
| Басниев и др., гл. XXIII + XXIV §1 | обучение | `runs/basniev/site/index.html` |
| Кузнецов, гл. 10 §10.1–10.4 | обучение | `runs/kuznetsov/site/index.html` |
| Латышова, §21 | репетиция | `runs/rehearsal_lat21/site/index.html` |

Для контрольных глав используйте `make control` с источниками из [HANDOFF](docs/HANDOFF.md).

Ролики и их паспорта: `runs/<глава>/video/<узел>/`.

## Запуск

```bash
make setup                      # Python 3.12 venv + зависимости (нужны uv, ffmpeg; для запасного голоса — espeak-ng)
export KMD_DATA=~/kmd_data      # папка с книгами: md/*.md (с метками <!-- page N -->) и pdf/*.pdf
make run CH=latyshova           # весь конвейер для главы → runs/latyshova/site/index.html
```

Для рендера видео установите FFmpeg и Cairo. На Linux для установки pycairo также нужны
`libcairo2-dev` и `pkg-config`. Ролик для конкретного узла можно собрать вместе с курсом:

```bash
make run CH=latyshova VIDEO_NODE=geo.latyshova.s20.01 VIDEO_FORMAT=short
# Или отдельно, с обновлением существующего сайта:
python -m kmd video latyshova geo.latyshova.s20.01 --format short
```

Видео собирают два движка (форматы `short` = 9:16, `long` = 16:9; MP4 и паспорт — в `runs/<глава>/video/<узел>/`):

| движок | как выбрать | как строит ролик | когда использовать |
|---|---|---|---|
| `vidpipe` (`video/vidpipe`, **по умолчанию**) | `--video-engine vidpipe --planner llm` | LLM-планировщик (сценарий → план кадров со спецификациями) идёт через `kmd/llm.py`: API-провайдер или очередь, ответы кэшируются в `runs/<глава>/llm/vidpipe.*`. Рендер Cairo, реальные данные Volve, метки «реальные данные / схема», QA-отчёт в `runs/<глава>/tmp/vidpipe/` | всегда. Без ключа LLM — код 3 и запросы в очереди, как у остальных этапов |
| `vidpipe` без LLM | `--planner rule` | план по правилам | только для черновика: на незнакомом узле кадры общие |
| `legacy` (`kmd/video`) | `--video-engine legacy` | спецификация сцены через `kmd.llm` → кадры matplotlib из моделей состояния `kmd/visuals` | так сделаны первые сданные ролики (шортс Латышовой, разбор Басниева) |

`make rebuild CH=<глава> VIDEO=1` пересобирает каждый ролик тем движком, которым он был сделан
(поле `engine` в паспорте). Для проверки речи заранее установите локальную модель faster-whisper
и укажите её имя или путь в `KMD_ASR_MODEL` (по умолчанию `medium`).

При запуске без ключа LLM конвейер переиспользует ответы из `runs/<глава>/llm/`, сохранённые сцены
и перерисовки. Отсутствующие сцены и перерисовки в этом режиме не блокируют сборку курса.
Чтобы запросить новые, запустите `.venv/bin/python -m kmd scenes <глава>` или добавьте `--with-scenes`
к команде `.venv/bin/python -m kmd run <глава>`. Отсутствующие ответы для обязательных этапов
по-прежнему попадают в очередь и возвращают код 3.

### Вопросы по урокам

Добавьте `OPENROUTER_API_KEY=...` в локальный `.env` и запустите
`python -m kmd serve --port 8767`. На любой странице курса откройте «Чат по книге» в правом нижнем углу.
Сервер ищет по фрагментам текущей главы с учётом выбранного урока и передаёт найденные
фрагменты и вопрос модели `baidu/ernie-5.5-flash-preview:free` через OpenRouter.
Каждая ссылка в ответе открывает конкретный фрагмент на странице `source.html`.

### Новая глава (тест)

1. По ТЗ вход состоит из Markdown главы с метками `<!-- page N -->` и изображений её страниц.
   Сохраните их в `$KMD_DATA`. Укажите в `chapters/<id>.yaml` домен, язык и страницы PDF.

   ```yaml
   id: new_chapter
   title: Название главы
   domain: geology
   language: ru
   book:
     md: md/new_book.md
     page_images: page_images/new_book
   segments:
     - pages: [7, 9]
   ```

   Для сканов используйте имена с номером страницы PDF, например `p7.png`, `page-008.jpg`
   и `9.png`. Если вместо отдельных изображений есть PDF, добавьте `book.pdf`: конвейер
   отрендерит страницы сам. Для режима **PDF-only** задайте только `book.pdf`. При необходимости
   укажите `language: en` и границы `start` и `end` внутри сегмента.
   Для скан-PDF установите Tesseract с нужным языковым пакетом.

2. Сохраните ключ и модель в локальном `.env`. Например, для OpenRouter:

   ```dotenv
   OPENAI_API_KEY=...
   OPENAI_BASE_URL=https://openrouter.ai/api/v1
   KMD_LLM_MODEL=<модель>
   ```

   Для Anthropic используйте `ANTHROPIC_API_KEY` и `KMD_LLM_MODEL`. Для DeepSeek V4 на OpenRouter
   по умолчанию отключён режим рассуждений, чтобы ответ целиком помещался в лимит JSON.
   `KMD_OPENROUTER_REASONING=default` оставляет настройки провайдера как есть.
   Без ключа запросы попадают в `runs/<id>/llm/pending/`. Команды `kmd llm show` и
   `kmd llm answer` показывают запрос и проверяют ответ по схеме перед записью в кэш.
3. Запустите `make run CH=<id>`. В режиме очереди код 3 означает, что нужны ответы.
   Рядом с сайтом сохранены `verify_report.json`, `course_report.json` и `template_coverage.json`.
   Последний показывает, какой шаблон и какая модель закрывают каждый видеоёмкий узел.
   При проверке слоя `kmd run` убирает неподтверждённое десятичное приближение из
   объяснения, если рядом есть символьное выражение. Затем он проверяет весь слой повторно.
   Применённые исправления отмечены в `verify_report.json` в поле `automatic_repairs`.
4. Для назначенного узла выполните `.venv/bin/python -m kmd video <id> <node_id> --format short|long`.
5. Для сдачи запустите `.venv/bin/python -m kmd export <id>`. В `runs/<id>/submission/` появятся
   учебный слой, покрытие, маршрутизация, задания, иллюстрации и паспорта по схемам организаторов.
   Сайт и MP4 открываются из соседних папок `site/` и `video/`. Для прогона по бурению экспорт
   можно выполнить сразу после `kmd route`. [Схемы организаторов](https://drive.google.com/drive/folders/1Oj6D3l_drhPSZHvUOEsBUQ9ocq9ZFoL7)

### Новый домен (сдвиг)

`python -m kmd domain <домен> --from-chapter <id>` — черновик доменного пакета (глоссарий RU/EN,
заблуждения, чек-лист физики, ИТ-мосты, словарь ударений) в `domains/<домен>/` с замером времени
в `BUILD.json`. Движок о геологии ничего не знает: всё предметное лежит в `domains/`.

### Исправить факт и пересобрать (одна команда)

Сгенерированные файлы руками не правятся. Правка — это патч узла в `overrides/<глава>/<node_id>.json`
и строка в журнале:

```bash
python -m kmd edit latyshova --target geo.latyshova.s20.04 --minutes 3 --what "уточнено условие применимости"
make rebuild CH=latyshova       # слой → проверка → маршрутизация → шаги → сайт
make rebuild CH=latyshova VIDEO=1  # также пересобрать имеющиеся ролики
```

Защита: «измените одно число в слое и пересоберите» — одна команда. Id утверждения виден в адресе
блока на странице шага (`#src-<claim_id>`). Ключ OpenRouter — `OPENROUTER_API_KEY` в `.env`.

```bash
make demo-edit CH=latyshova CLAIM=geo.latyshova.s20.04.c02 OLD=1856 NEW=1857          # ~1 мин
make demo-edit CH=latyshova CLAIM=geo.latyshova.s20.04.c02 OLD=1856 NEW=1857 VIDEO=1  # и ролики
```

Команда пишет патч в `overrides/<глава>/<узел>.json` (сливая с уже имеющимся), запись в
`edits/journal.jsonl`, пересобирает главу (заново спрашивается только изменённый узел: модель
`KMD_DEMO_MODEL`, по умолчанию deepseek/deepseek-v4.1-flash-1017) и печатает ссылку на страницу шага
с проверкой, что новый текст на ней есть. Число из правки человека, которого нет в книге, проверка
помечает предупреждением `number_by_editor`, а не ошибкой; цитаты автора остаются дословными.

Журнал ручных правок: `edits/journal.jsonl` (минуты, коммит). Метрики стоимости:
`python -m kmd.metrics` сохраняет `runs/metrics.json`. Суммы, сообщённые API, записаны отдельно
от оценок по токенам. Оценки можно настроить через `KMD_PRICE_IN` и `KMD_PRICE_OUT` в USD за миллион.
Для работы над роликом укажите `--kind video` при записи в журнал, для разбора с ментором — `--kind mentor`.
Доля ручного времени рассчитана по журналу и замеру последнего полного запуска `kmd run`.

### Модуль проверки (закладки)

```bash
.venv/bin/python -m kmd ingest <id>
.venv/bin/python -m kmd check <пакет>/package.json --chapter <id> --out remarks.json
```
Для пакета организаторов с `items`, `frames` и `scenes` поле `remarks` в JSON соответствует
схеме сдачи. Храните кадры по относительным путям, указанным в пакете.
Внутренний формат `schemas/external_package.schema.json` также поддерживается.

## Как устроено

`docs/ARCHITECTURE.md` — этапы и их артефакты; `docs/PLAYBOOK.md` — порядок работы команды;
`MANIFEST.yaml` — модели и инструменты, что уходит во внешние сервисы; `docs/TZ.md` — задание.

```
глава (md + сканы) → ingest → units.json (единицы главы со страницами)
  → layer → layer.json (учебный слой: узлы, утверждения с цитатой и страницей) + coverage.json (100 %)
  → verify (код: цитата есть на странице, каждое число есть в источнике, покрытие, ссылки)
  → route → routing.json (формат узла по типу трудности и видеоёмкости)
  → scenes → спецификации сцен (объекты, параметры, инварианты, допущения, класс кадра)
  → course → страницы шагов, задания, карточки и иллюстрации
  → video (по запросу) → vidpipe → MP4, QA и паспорт
  → site/ (офлайн-курс с доступными роликами)
```

Тесты: `make test`.
